# Hardware acceptance protocol — pending

Do not mark these passed based on compilation, synthetic sysfs or fake D-Bus tests. Capture versions, phone model/Android version, USB driver, topology and timestamp; redact identifiers before sharing.

1. Record `ip -j route`, `ip -6 -j route`, `nmcli device`, active profiles and resolver status. Enable native USB tethering. Confirm exactly the tethering interface is selected; MTP/ADB alone must not count.
2. Connect default mode. Verify DHCP address, gateway, phone DNS and interface-bound DNS/TLS pass. Confirm the high-metric fallback route exists and other lower-metric routes remain preferred; if no better route exists the phone will be the default. An unrelated working Wi-Fi connection must never make a disconnected USB test pass.
3. Connect with explicit full-system preference. Confirm the current UID's preferred IPv4 route, DNS resolver link selection and IPv6 route individually. Test normal browser, TCP and a real UDP destination, and IPv6 only if advertised by the phone. Inspect phone-side transfer counters. Audit DNS captures on unrelated interfaces in an isolated lab before claiming leak prevention; this build does not guarantee it.
4. Unplug/replug cable, toggle tethering, move USB ports, disable mobile data, simulate internet probe failure, suspend/resume and restart NetworkManager. Confirm immediate/degraded status, bounded retries, no duplicate profiles and no stale Connected state. A probe-specific failure should degrade rather than repeatedly tear down DHCP.
5. Quit normally, SIGINT, SIGTERM and finally SIGKILL in an isolated lab. Compare routes/DNS/profiles to baseline. For SIGKILL allow the 90-second checkpoint deadline. Test restoration of a previously active profile on the same USB device. Record rollback errors; do not assume success.
6. Verify existing Wi-Fi phone hotspot traffic. Test Wi-Fi Direct only with an actual compatible phone/adapter. Explicitly probe its advertised gateway, not a presumed address. HTTP CONNECT success demonstrates TCP only. Full-system proxy tunneling remains unimplemented.
7. Pair a phone offering Bluetooth PAN/NAP; enable Android Bluetooth tethering; establish PAN through desktop NetworkManager. Confirm app detection, interface-bound DNS/TLS and disconnection behavior. Lack of PAN is a meaningful unsupported condition, not a fallback to DUN.
8. Measure sustained `iperf3` throughput against a controlled reachable endpoint, idle/loaded latency, jitter, packet loss, phone DNS time, reconnect wall time and process RSS/CPU for USB/Wi-Fi separately. Record methodology and phone thermal/battery state. Do not fabricate values.
9. Install/launch/remove each package on its target distro. Test Wayland Sway, KDE, GNOME and an X11 session separately, tray host absent/present, no Polkit agent, authorization denied and stale/malformed configuration. Reconnect and cleanup must work without running the GUI as root.
