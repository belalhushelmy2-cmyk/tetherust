# Tetherust progress

Started 2026-10-23; validation continued 2026-10-24 (Africa/Cairo). Independent Linux Cargo application in `tetherust/`. Original Cliprust application remains separate. Current work is the 0.3.0 milestone below; earlier numbered checkpoints record historical scope.

1. **Research — implemented.** Requested reference projects and NetworkManager API inspected. Licensing and protocol limits recorded in docs/RESEARCH.md. No proprietary or unlicensed tunnel code reused.
2. **Native USB backend — implemented, hardware acceptance pending.** Native D-Bus device enumeration, sysfs USB ancestry/driver validation, DHCP/IPv6, volatile connection, Polkit-managed authorization, selected-device recovery checkpoint and D-Bus lifetime ownership. CLI doctor/devices/connect/verify and single-instance locking.
3. **Slint GUI — implemented and rendered on private Sway.** Dashboard, device selection, settings and redacted/advanced logs, actual action callbacks, optional native tray, notifications, autostart, byte counters and session duration. No invented device/traffic data. Connected requires interface-specific DNS and certificate-verified HTTPS.
4. **Wi-Fi Direct/proxy — partial.** Wi-Fi/P2P capability inventory, observation of desktop-established links, advertised-gateway standard HTTP CONNECT/TLS diagnostic. Automatic joining and TUN-to-proxy system routing are outstanding. Diagnostic success is never presented as arbitrary UDP support.
5. **Android companion — implemented in 0.2.0, phone acceptance pending.** Signed Kotlin APK, visible foreground service, cellular-bound socket forwarding, Android Keystore TLS identity and authorized-ADB pairing. Host Kotlin/Rust TLS/TCP/UDP interoperability passes. No installation or runtime validation was performed on the phone after the user prohibited further phone operations.
6. **System routing/DNS — native USB preference and companion TUN implemented; comprehensive leak protection outstanding.** Default uses high-metric fallback routes/DNS; explicit Prefer phone uses low-metric routes and negative DNS priority on a temporary profile. Existing LAN routes remain. No firewall/sysctl/MTU/TTL changes. VPN policies, alternate IPv6 and private application DNS are not comprehensively controlled.
7. **Reliability — implemented with limits.** One-second link inventory, 15-second DNS/TLS checks, capped 32-second reconnect backoff, recovery watchdog, clean command/channel/signal exit, bounded queues and journals. In-flight probes may delay commands up to 12 seconds; D-Bus operations have 25-second timeouts. Resume/crash tests on a real USB phone remain pending.
8. **Bluetooth/diagnostics — partial.** Existing NetworkManager Bluetooth PAN links can be verified/monitored; pairing and establishing PAN use desktop settings. In-app Bluetooth activation, device pairing and protocol-specific throughput/jitter benchmarking remain outstanding.
9. **Packaging — development recipes and artifacts.** Signed Android APK, PKGBUILD, AppImage, DEB, generic tar.gz/source archive and a separate Ubuntu 22.04 CI workflow. Local artifacts target the current host ABI; CI execution and cross-distribution installation acceptance are not claimed.

This is a tested USB-first development milestone, not completion of the whole requested product. No USB phone/PAN peer/compatible Wi-Fi Direct phone was available. All hardware-dependent acceptance remains explicitly pending in TEST_RESULTS.md and docs/HARDWARE_ACCEPTANCE.md.

Final software checkpoint: 12 core tests plus the explicitly run private-bus contract/state test pass; formatting and Clippy pass. Release GUI and packaged AppRun pass private Wayland interactions. Generated package checksums and PKGBUILD source verification pass. The tray action now checks for an actual registered host and restores the window if it disappears; Disconnect clears a pending retry even when no session has activated. Hardware and cross-distribution acceptance remain pending.

## 0.2.0 companion milestone (2026-10-24)

The laptop initially reported a connected Motorola USB device with no native USB tethering interface. Before the user's restriction, authorized read-only ADB identified an Edge 60 Fusion / API 36. The user then explicitly said not to do anything to this phone. No install, app launch, pairing read, forward, file transfer or further phone probe was performed after that instruction. All subsequent tests are offline/laptop-only with ADB disabled.

Built a signed non-debuggable Kotlin companion APK; added certificate-pinned/authenticated ADB forwarding, local SOCKS5 TCP/UDP translation, desktop pairing/install controls and embedded tun2proxy with a dedicated NetworkManager-owned TUN lifetime. The actual Kotlin engine and Rust bridge pass host-local TLS/TCP/UDP tests; the packet engine answers a raw virtual-DNS packet. This supersedes the earlier statement that the companion/TUN transport is unimplemented. Real Android service/Keystore/cellular/USB/system-routing acceptance remains pending until separately authorized.

Additional Linux acceptance: a real NetworkManager in an isolated user/network/mount namespace created the owned TUN and its DNS/routes, served DNS through the actual kernel TUN/tun2proxy engine, cleaned up on disconnect, reconnected, and removed routes when the dedicated D-Bus client disappeared. The client dropped all capabilities before opening the user-owned TUN. The host network and phone were not used by that test.

## 0.3.0 phone-effective-network milestone (2026-10-24)

Supersedes the 0.2.0 cellular-only path above. The companion now captures Android's app-default Network (including an applicable VPN), resolves and creates TCP/UDP sockets on that same network, and closes authenticated clients and sockets on network/capability/route/DNS changes. No VpnService, protect(), cellular request or phone-wide route changes. Protocol 2 carries path status and per-stream generation/policy leases. Independent phone/Linux HTTPS probes must match; strict mode pins observed exit/network, requires applicable default IPv4 VPN routes, and refuses IPv6 without default IPv6 VPN routes. Internal split VPN rules remain opaque; probe evidence is not universal leak proof.

Strict sharing requires Full-Tunnel plus a Polkit-authorized fixed nftables Kill Switch. Root is confined to a small installed helper; its table survives GUI crashes and failed reconnects, and only explicit Disconnect/exit/recovery removes it. Documented LAN exceptions remain. No live host firewall changes were made during development. Optional local HTTP/SOCKS proxy paths are TCP-only without direct fallback; they cannot claim strict VPN state. Optional pinned Wi-Fi uses an explicitly enabled LAN listener and untrusted mDNS discovery with existing USB-paired identity.

The user's earlier prohibition on phone operations remains in force. No ADB/device query, installation, pairing read, forward, launch, phone network probe or Wi-Fi discovery was executed during this milestone. All physical A/B/C VPN, split-exclusion, lockdown, hotspot and USB unplug/replug acceptance stays pending. Build/test evidence for this milestone is maintained in TEST_RESULTS.md.

Final namespace strengthening: the older harness had not actually enforced capability dropping as its historical report claimed. The harness now removes capabilities from the entire test client before launch, locks NOROOT/no_new_privs, and verifies zero effective/permitted masks. Ordinary TCP and UDP application sockets now pass through the actual kernel TUN, virtual DNS, Rust bridge and Kotlin TLS gateway in that isolated namespace. This passes without phone access and is not an Android VPN acceptance claim.
