# Tetherust architecture

Independent Cargo project, Linux only, inside the existing checkout. Rust + Tokio + native Slint/Winit/software renderer. No browser, webview or Python runtime.

- `device`: validated interface names, sysfs USB ancestry/driver classification, kernel interface byte counters. Names are candidates, never proof of phone identity. Does not read USB serials.
- `network`: native system D-Bus NetworkManager integration. Enumerates device/IP configuration; creates only volatile, non-autoconnecting USB profiles; binds them to its D-Bus lifetime. A selected-device checkpoint is created before activation. Normal disconnect restores it. Crash recovery depends on NetworkManager remaining alive and the timeout elapsing. No custom root helper, nftables or persistent DNS edits are necessary for the native path; NetworkManager enforces its existing Polkit policy. Authentication requires the desktop's Polkit agent.
- `health`: interface-bound UDP DNS queries with unpredictable transaction IDs, bounded parsing, matching questions and connected peer; then certificate-verified HTTPS to the resolved probe host. Ignores environment proxies, rejects redirects/captive portal content, bounds response sizes and timeouts. Internet status requires both DNS and TLS success. Reports one verified address family, not both. Kernel preferred-route diagnostic uses `ip -j route get`; it checks only the probe destination and current user/policy context.
- `session`: one async controller owns activation, supervision, statistics and recovery. Bounded command queue, latest-value watch snapshots, one-second inventory checks, 15-second internet checks, 1/2/4/8/16/32-second reconnect backoff. Activation failures and vanished links retry; a failed internet probe degrades without flapping a physical link. A failed rollback stops automatic reconnection for inspection. SIGINT/SIGTERM/channel close/window quit perform recovery. A frozen/killed process relies on the 90-second NetworkManager watchdog. D-Bus calls time out after 25 seconds; in-flight operations may delay a command/shutdown. Checkpoints are not renewed while suspended: resume may intentionally require reconnection.
- `config` / `storage`: private JSON settings, atomic writes, 100-session JSONL history, 200-event log ring, no SQLite daemon. Advisory flock prevents concurrent connection/GUI instances. Redacted exports contain fixed event labels, never backend errors/IPs/phone identifiers. Locally displayed detailed errors may contain network information. Logs are memory-only until explicitly exported. Statistics are interface-wide, including other programs and local traffic, not app-exclusive measurements.
- `ui`: main-thread Slint interface, async worker, timer-driven snapshots, functional dashboard/device/settings/log actions. Existing Wi-Fi/PAN observation is read-only and disconnect does not take down a desktop-owned link. Optional KSNI/DBusMenu tray; explicit Hide to tray only when a StatusNotifierItem host is registered, explicit Quit. If the tray host disappears, the window is shown again. Desktop notifications use the session D-Bus Notifications service. Clipboard log copying uses wl-copy or xclip; failures are shown and export remains available. Autostart uses a per-user desktop file; no Sway configuration edits.

## Routing contract

Default USB mode obtains addresses and a metric-60000 fallback default route needed for interface-bound probes; lower-metric existing routes remain preferred, but the phone becomes the default when no better route exists. Opt-in 'Prefer phone' creates a temporary low-metric default route, DHCP DNS with negative priority and '~.' routing domain, and normal IPv6 autoconfiguration. Existing on-link routes remain. No global sysctls, MTU, TTL, nftables, firewall flushes or TLS exceptions are used. Existing VPN/policy routing, IPv6 on other links, private application resolvers and other DNS configurations can override expectations. This is not a VPN/kill switch and does not guarantee system-wide leak prevention. Native USB carries the protocols supported by Android (normally TCP/UDP, IPv4 and optionally IPv6); this release cannot certify them without hardware acceptance.

## Ownership and limitations

Checkpoints cover only the selected interface. If another network manager/user changes that same interface during a session, restoring the earlier checkpoint can also undo those intervening changes. Avoid concurrent control of the selected link. Unrelated interfaces/firewall rules are untouched.

Wi-Fi Direct discovery/join, general Wi-Fi proxy routing, automatic Bluetooth pairing/activation, custom DNS editor, throughput/jitter benchmark UI and independent DNS/IPv6 leak auditing remain future stages. They are not presented as working controls.

## 0.2.0 companion architecture

`companion` enumerates local ADB inventory, pairs only on an explicit action, creates/removes an owned ephemeral ADB forward, pins the exact Android Keystore certificate and verifies TLS handshake signatures, authenticates with the paired token, and exposes a separately authenticated local SOCKS5 TCP/UDP bridge. No phone credentials appear in process arguments or event exports. UDP uses bounded, cancellation-safe, length-framed datagrams inside TLS.

`android/` is a Kotlin Android app plus an SDK-only reproducible APK build. A visible foreground service requests cellular connectivity and uses Network.socketFactory/getAllByName/bindSocket for outbound TCP, DNS and UDP. The pairing provider authorizes only shell UID 2000 and its own app UID; this trusts the user's already-authorized debugging hosts. The app never starts sharing on boot. A host-JVM fixture runs the same pure Kotlin ProxyEngine for real encrypted protocol tests without an Android device.

`tunnel` opens an existing NM-created TUN with IFF_TUN/IFF_NO_PI as its assigned ordinary-user owner. Embedded tun2proxy 0.8.6 (MIT) converts packets to the local authenticated SOCKS bridge with virtual DNS. NetworkManager creates only tetherust0, a volatile/non-autoconnecting profile, user/group ownership, IPv4/IPv6 half-default routes and negative-priority DNS. Native LAN routes remain more specific. A dedicated D-Bus connection owns this profile so startup timeout/drop cannot bind it to the long-lived inventory bus. No kernel TUN or global routes are created by the offline packet/JVM tests. Real full-system phone routing and cleanup remain unverified.

## Protocol 2 / app-default network (0.3.0)

The earlier cellular-specific companion description is superseded. A NetworkCallback observes the per-app default Android Network. TCP sockets, bound UDP sockets and DNS all capture it; no underlay request or second VpnService is created. Authenticated command 240 returns bounded JSON path status. Every data stream starts with command 241, a strict flag and unsigned 64-bit network generation, followed by a TCP/UDP request or command 242 (independent phone HTTPS exit probe). Unknown/old clients fail closed. The phone rejects stale generations; callback changes close existing clients and datagram sockets. The desktop compares its separately forwarded HTTPS trace with the phone probe, pins strict network/exit across retries, and polls path state. It cannot inspect internal VPN app decisions or claim every destination is VPN-routed.

The fixed root helper applies/removes only inet/tetherust_guard, serializes operations and accepts no supplied rules. The unprivileged client only launches an installed helper with root-owned, non-writable ancestors through Polkit. Guard lifetime is intentionally independent from the volatile TUN so a GUI crash does not restore direct internet while strict sharing was armed. Ordinary graceful Disconnect releases both. LAN exceptions and manual recovery are documented in README. Optional Wi-Fi reuses pinned identity/authentication; mDNS is only an untrusted locator. Local loopback proxy mode resolves names at its proxy and rejects UDP/strict VPN policy.
